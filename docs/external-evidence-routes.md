## Common security and failure contract

- Shared account state remains database-authoritative and online-only. Signed-out, expired, unavailable, malformed, ambiguous, or revoked routes fail closed with a visible retry or fallback.
- Provider and account secrets never enter shared records, browser storage, Broadcast payloads, logs, exports, assistant context, or durable memory. Account credentials belong only in the Supabase Vault path; service credentials remain server-side.
- Every accepted record carries provider, route version, stable source identity, occurrence range, local date, freshness, and source tier. Duplicate identities return the original receipt; conflicting reuse fails visibly.
- Raw files and provider payloads are discarded after an atomic normalized import. Hero metadata never contains amounts, balances, locations, course content, health diagnostics, repository content, or provider payloads.
- Provider presence, connection, import, volume, wealth, score, and product usage never award XP. Only the behavior named in the versioned mapping can qualify.

## Primary-source record

The contract records the exact checked URLs and findings. Key boundaries are supported by current official material:

- Barclays explains explicit consent and registered third-party access in [Open Banking](https://www.barclays.co.uk/ways-to-bank/open-banking/); the Open Banking Directory documents [regulated enrolment, certificates, and software statements](https://www.openbanking.org.uk/directory/), and the current standard limits [Account Information Services](https://standards.openbanking.org.uk/customer-experience-guidelines/account-information-services/latest/) to AISPs with user consent.
- Apple documents [HealthKit](https://developer.apple.com/documentation/healthkit), automatic iPhone [step-count samples](https://developer.apple.com/documentation/healthkit/hkquantitytypeidentifier/stepcount), Shortcuts [Find Health Samples](https://support.apple.com/guide/shortcuts/intro-to-find-and-filter-actions-apd3c845e881/ios), [URL requests](https://support.apple.com/guide/shortcuts/request-your-first-api-apd58d46713f/ios), and the broad [Health XML export](https://support.apple.com/guide/iphone/share-your-health-data-iph5ede58c3d/ios).
- Eight Sleep documents [the sensitive data it collects and its data-copy request](https://help.eightsleep.com/en_us/what-data-does-the-eight-sleep-tracker-collect-Hk79MjgUm), [user-directed sharing and Apple Health linking](https://www.eightsleep.com/app-terms-conditions/), and [editable finalized sleep sessions](https://help.eightsleep.com/en_us/how-do-i-edit-or-delete-my-sleep-session-HynxgIj4). These sources do not establish a public read API or routine export.
- GitHub recommends [GitHub Apps over OAuth apps](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/differences-between-github-apps-and-oauth-apps), documents [minimum app permissions](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/choosing-permissions-for-a-github-app), publishes [REST rate-limit behavior](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api), and requires [server-side webhook signature validation](https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries) for the documented [pull-request event surface](https://docs.github.com/en/webhooks/webhook-events-and-payloads).

## Revisit rule

Later tickets may implement only the approved route and tests in the JSON contract. A current official provider change, a missing required field, or a request for broader data or authority reopens KAN-263's route decision; it never authorizes an undocumented API, credentialed scraping, browser-login automation, or a write-capable provider operation.

# Feature Status

Use this matrix when updating docs or UI copy. The allowed states are:

- `real`
- `local-only/degraded`
- `placeholder/simulated`

| Area | Status | Notes |
| --- | --- | --- |
| Supabase account persistence | `real` | Required for shared Sabah One data. Authenticated RLS reads, one transactional semantic-mutation RPC, idempotent receipts, tombstones, explicit ordering, private per-account Broadcast, and version-gap recovery make the database authoritative across devices. Offline, anonymous, expired, or obsolete clients fail closed; there is no durable offline queue or user conflict chooser. |
| Encrypted Secrets vault | `real` | The signed-in Secrets surface stores passwords, API keys, tokens, database credentials, private keys, and webhooks as account-owned encrypted Supabase Vault values with separate searchable metadata. Values are masked by default and fetched lazily one at a time for immediate Reveal or Copy. They never enter shared records, browser storage, Broadcast payloads, logs, exports, or assistant context, and are cleared from UI state on Hide, navigation, focus loss, sign-out, account switch, or refresh. Archive/Restore is reversible; permanent deletion, bulk export, sharing, autofill, and offline access are intentionally absent. |
| Device persistence | `real` | Limited to machine-bound paths, native approvals, fingerprints, process state, logs, and local model/audio settings. Existing Deepgram and ElevenLabs device keys are copied non-destructively into the account vault by stable source identity while their original device settings remain available during migration. Old shared snapshots are resolved automatically: database values win for matching records, safe local-only additions are preserved, ambiguous data is quarantined, and verified copies are retired without a prompt. |
| Google Calendar OAuth | `real` | Supports multi-account Calendar connections plus linking the matching Sabah One Google sign-in to the same-email Calendar account. Browser builds now use GIS authorization codes plus the hosted `google-calendar-oauth` Edge Function and server-stored refreshable credentials instead of treating 1-hour browser tokens as durable transport. The hosted function validates Supabase auth internally, is deployed with JWT verification disabled so asymmetric `ES256` Sabah One sessions are accepted, and the release workflow now applies the `google_calendar_credentials` schema before deploying the hosted auth path. |
| Google Calendar sync | `real` | Events and calendars sync through the Google Calendar API with account-level reconnect states. Passive sync is non-interactive, Calendar tab navigation is read-only, `Sync` stays passive, reconnect-required only comes from confirmed auth failures, missing hosted credentials, or real revoke conditions, and legacy browser tokens are migration diagnostics instead of live transport. Google is the provider source of truth: complete successful fetches remove provider rows Google no longer returns, while failed or partial fetches preserve the account database cache. Stale device calendar copies are retired automatically and trigger a provider refresh; they never open a database/device chooser. |
| Google Calendar diagnostics in Debug tab | `real` | `Debug -> Network / APIs` shows Sabah One auth context, hosted backend readiness, hosted credential source and health, redacted current access-token expiry, refresh-failure metadata, legacy browser-token migration state, per-account passive-sync eligibility, trigger source, blocked reasons, wrong-account detection, skipped destructive removals, fetched event count, added/updated count, relinked cached event count, cached Google event count, visible Google event count, a local-only persisted runtime timeline with request IDs and normalized failure codes, and a manual passive auth check that probes Calendar access without mutating sources or events. |
| Manual calendar accounts | `real` | Manual calendar records belong to the signed-in Sabah One account database; provider transport can remain local, but the shared Calendar surface is unavailable offline. |
| Chat assistant with hosted OpenAI | `real` | Real when Supabase is configured and the `assistant-openai` Edge Function is deployed. Browser builds now use a hosted GPT-5.4-family model as the conversational brain: the model chooses `reply`, `clarify`, `confirm`, or `tool_calls`, Sabah One validates and executes locally, and GPT narrates the final visible reply from verified results. Settings can switch the hosted path between GPT-5.4, GPT-5.4 mini, and GPT-5.4 nano so users can trade peak quality for lower token cost. Chat now shows an `Estimated OpenAI conversation total` derived from OpenAI-reported usage for hosted turns only; this is not an exact billed-per-conversation amount. The live hosted path is benchmark-gated on `master` before deployment. |
| Chat assistant with Ollama | `real` | Real when Ollama is reachable locally. Ollama follows the same GPT-led orchestration shape as hosted mode instead of falling back to local regex intent parsing. |
| Chat conversation export | `real` | The Chat surface can copy the active conversation to the clipboard or export it as a Markdown file so the transcript can be dropped into Codex or other tools without reformatting. |
| Lina activity log and undo | `real` | Chat and voice assistant mutations record account-backed audit entries with grounded undo metadata. Undo covers the documented task, prayer, calendar, finance, and knowledge mutations. |
| Global Inventory | `real` | Account-backed Owned and Needed records support search, category/project/location filters, optional labelled length/width/height dimensions, flexible specifications, low-stock flags, add/edit/archive, quantity changes, Need more, atomic acquisition, and reviewed multiline import. Dimensions accept partial axes with an explicit unit, survive legacy-client edits, and carry into newly acquired items. Each managed Project has a catalogue-key-filtered Inventory tab linked to the global catalogue. Historical Capture records are recoverable tombstones with no active UI or mutation path. |
| Codex Inventory plugin | `local-only/degraded` | The private `sabah-one-inventory` plugin contains a planning skill and remote authenticated MCP server with seven narrow tools. Local packaging and database policy are implemented; cross-project completion remains gated on a production Supabase OAuth beta handshake, per-client consent, revocation, and a fresh Codex task after deployment. |
| Chat assistant without a live AI provider | `local-only/degraded` | Lina now refuses to guess or execute assistant actions from chat unless a live hosted or Ollama planner is available. Users can still use the app surfaces directly. |
| AI diagnostics in Debug tab | `real` | The Debug surface includes runtime status, Supabase session details, hosted health and smoke tests, Ollama checks, circuit-breaker reset controls, the latest planning bundle, raw planner response, model turn, validator verdict, pending confirmation state, execution payloads, raw narration response, final assistant message, latest-turn OpenAI usage estimates, factual last-7-day OpenAI project billing and usage buckets when the separate admin-backed billing function is configured, and the latest dashboard-focus trace so task recommendations can be debugged when GPT picks or falls back. If admin billing access is missing, the panel shows a truthful unavailable state instead of simulated billing data. |
| User-facing Database / AI Health Center | `real` | Dashboard and Settings show the authoritative database session, private Broadcast state, Google Calendar, hosted OpenAI, Ollama, and Voice readiness. Reconnect is automatic; there is no sync decision modal. Diagnostics never expose raw tokens. |
| Night Compass dashboard visual contract | `placeholder/simulated` | KAN-245 provides selected 1440 by 900 art direction and an authoritative deterministic contract for a prayer-first Prayer -> Learn -> Move -> Tasks hierarchy. Production Dashboard behavior is unchanged; the raster is not functional proof, and a later implementation ticket owns React/CSS and rendered runtime acceptance. |
| Daily Learn and Move progression | `real` | Signed-in accounts have versioned editable Learn and Move templates, five cumulative levels, local-date progress logs, positive-progress path locking, confirmed pillar/date-only reset, and shared reminder preferences. Writes remain online-only and database-authoritative; native notification permission and scheduling state remain device-owned. Dashboard rendering is owned by a later ticket. |
| Dashboard task snapshot and smart Up Next | `real` | The Dashboard now surfaces a compact task queue with urgent counts plus a GPT-first `Up Next` recommendation. Sabah One builds grounded local candidates from tasks, habits, prayer tasks, calendar pressure, streak state, and recent feedback, lets hosted GPT review that candidate pool once per local day, and relies on the local ranker for live reshuffling the rest of the day. Prayer tasks are first-class and only enter `Up Next` during the active prayer window, in order, instead of being treated like timeless daily habits; when the Dhuhr or Maghrib window is active and the paired prayer is still upcoming, the recommendation copy now treats Dhuhr/Asr and Maghrib/Isha as paired suggestions instead of phrasing them as isolated prayers. If hosted AI is unavailable, invalid, or the user is in Ollama mode, the dashboard now says so explicitly instead of implying GPT reviewed the list, and duration chips only appear when the time comes from grounded task or calendar data instead of heuristics. |
| Voice assistant | `local-only/degraded` | Shares the same GPT-led assistant runtime as chat, including model-first intent recognition, confirmation handling, grounded ID validation, narrated final replies, and transcript correction memory for phrases the user fixes with "No, I said ...". With wake word plus STT/TTS available, Lina runs a hands-free turn-based voice session with spoken acknowledgement, a mic-ready tone after the microphone is truly live, live transcript preview, more patient 2.5-3.0 second pause handling before ending a spoken turn, automatic follow-up listening, and wake-word sessions recorded into Chat history as separate conversation threads. Settings can turn Lina off completely without removing Chat. If no live planner is available, voice refuses to guess instead of falling back to local parser commands. |
| Wake word | `real` | OpenWakeWord runs locally in-browser via WASM. |
| Deepgram speech-to-text | `real` | Requires a configured API key. |
| Browser speech fallback | `local-only/degraded` | Usable where supported, less reliable than Deepgram. |
| ElevenLabs speech output | `real` | Requires env configuration. |
| Browser speech output | `local-only/degraded` | Used when ElevenLabs is unavailable. |
| Prayer times, outcomes, deadlines, and reminders | `real` | One shell-level provider owns the validated timetable and canonical account-backed prayer records. Native reminder timers remain device runtime state; shared outcomes are unavailable offline. |
| Clock surface (multi-timer and stopwatch workspace) | `real` | Timers and stopwatches persist as independently mutable account records. The surface supports custom cards, laps, alarm sounds, and acknowledgement-required alerts; shared Clock data is unavailable offline. |
| Finance accounts, budgets, and savings goals | `real` | Account-backed records are implemented and isolated per signed-in user. |
| Health fast food log | `real` | Account-backed quick-entry journaling and recent-history views are implemented. |
| Monzo import | `real` | Live API path exists when configured. |
| Knowledge base and lifestyle tracker | `real` | Account-backed CRUD converges across signed-in devices. Knowledge entries can move between topics without recreation. |
| Projects reference hub | `real` | Projects is a searchable catalogue with separate Pinned, Projects, and reversible Archived sections. Cards expose direct pin, archive, and unarchive controls; pointer, touch, keyboard, and move-menu reordering persist shared catalogue order without affecting device-only roots, approvals, logs, or processes. Cards still open an accessible desktop drawer or mobile full-screen sheet with links, prerequisites, copyable setup guidance, local run recipes, and secondary access to Board, Milestones, and Wiki. The private catalogue remains keyed by stable `catalogKey`; native Sabah One retains its approved-profile launcher protections, while web Sabah One remains reference/copy-only. |
| Trips planner | `real` | Account-backed multi-country trips, ordered legs, itinerary items, bookings, budgets, and explicit calendar import are implemented. |
| GitHub integration | `placeholder/simulated` | Simulated connection flow only. |
| Slack integration | `placeholder/simulated` | Simulated connection flow only. |
| Linear integration | `placeholder/simulated` | Simulated connection flow only. |

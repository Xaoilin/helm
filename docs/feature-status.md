# Feature Status

Use this matrix when updating docs or UI copy. The allowed states are:

- `real`
- `local-only/degraded`
- `placeholder/simulated`

| Area | Status | Notes |
| --- | --- | --- |
| Supabase sign-in and sync | `real` | Optional cloud sync when Supabase is configured and the user signs in. Signed-in shared app data reads from Supabase only, writes to Supabase only, waits for auth bootstrap before domain providers mount, uses best-effort realtime invalidation for already-open devices, and reviews old device copies only when meaningful user data or user preferences conflict with Supabase. The authenticated initial-save guard records the loaded database JSON, so a first real write that differs from an existing database row is not discarded as startup noise. |
| Local persistence | `real` | Signed-out mode uses Tauri file storage when available, with `localStorage` as fallback. Signed-in mode treats old local copies as migration/drift candidates: identical copies and system/cache metadata drift are cleaned up, local-only user data imports when the database group is empty, and real user-data conflicts open a Settings review modal with field-level summaries and redacted highlighted JSON diffs. |
| Google Calendar OAuth | `real` | Supports multi-account Calendar connections plus linking the matching HELM Google sign-in to the same-email Calendar account. Browser builds now use GIS authorization codes plus the hosted `google-calendar-oauth` Edge Function and server-stored refreshable credentials instead of treating 1-hour browser tokens as durable transport. The hosted function validates Supabase auth internally, is deployed with JWT verification disabled so asymmetric `ES256` HELM sessions are accepted, and the release workflow now applies the `google_calendar_credentials` schema before deploying the hosted auth path. |
| Google Calendar sync | `real` | Events and calendars sync through the Google Calendar API with account-level reconnect states. Passive sync is non-interactive, Calendar tab navigation is read-only, `Sync` stays passive, reconnect-required only comes from confirmed auth failures, missing hosted credentials, or real revoke conditions, and legacy browser tokens are now migration diagnostics instead of live transport. Profile-linked HELM Google accounts now repair the hosted Calendar credential directly when a refresh token is present, and hosted refreshable credentials clear stale local revoked/reconnect state while preserving explicit wrong-account failures. Event sync reconciles newly discovered and orphaned pre-reconnect source rows before fetching events, and relinks fetched provider events that were cached under stale source ids, so a successful source-list fetch cannot silently skip every event payload. Google is now the live source of truth for provider data: successful fetches remove stale provider calendars and in-window events that Google no longer returns, while failed or partial fetches preserve cache. Calendar drift never opens the database/device review modal; stale device calendar cache is cleared and a Google refresh is requested automatically. The Calendar header now labels its count as visible events, and the manual Sync button is explicitly a passive Google refresh into HELM's cache. |
| Google Calendar diagnostics in Debug tab | `real` | `Debug -> Network / APIs` shows HELM auth context, hosted backend readiness, hosted credential source and health, redacted current access-token expiry, refresh-failure metadata, legacy browser-token migration state, per-account passive-sync eligibility, trigger source, blocked reasons, wrong-account detection, skipped destructive removals, fetched event count, added/updated count, relinked cached event count, cached Google event count, visible Google event count, a local-only persisted runtime timeline with request IDs and normalized failure codes, and a manual passive auth check that probes Calendar access without mutating sources or events. |
| Local calendar accounts | `real` | Local accounts and sources work without cloud sync. |
| Chat assistant with hosted OpenAI | `real` | Real when Supabase is configured and the `assistant-openai` Edge Function is deployed. Browser builds now use a hosted GPT-5.4-family model as the conversational brain: the model chooses `reply`, `clarify`, `confirm`, or `tool_calls`, HELM validates and executes locally, and GPT narrates the final visible reply from verified results. Settings can switch the hosted path between GPT-5.4, GPT-5.4 mini, and GPT-5.4 nano so users can trade peak quality for lower token cost. Chat now shows an `Estimated OpenAI conversation total` derived from OpenAI-reported usage for hosted turns only; this is not an exact billed-per-conversation amount. The live hosted path is benchmark-gated on `master` before deployment. |
| Chat assistant with Ollama | `real` | Real when Ollama is reachable locally. Ollama follows the same GPT-led orchestration shape as hosted mode instead of falling back to local regex intent parsing. |
| Chat conversation export | `real` | The Chat surface can copy the active conversation to the clipboard or export it as a Markdown file so the transcript can be dropped into Codex or other tools without reformatting. |
| Lina activity log and undo | `real` | Chat and voice assistant mutations now record local-first audit entries in the Activity surface, including actor, source transcript, execution details, and undo metadata where HELM has a grounded inverse operation. Undo currently covers assistant-created tasks, ordinary task completion with gamification rollback, prayer completion with task/gamification/canonical-outcome rollback, assistant-deleted tasks, assistant-created or rescheduled calendar events, assistant-recorded finance transactions, and assistant-created knowledge notes. |
| Universal Capture Inbox | `real` | Local-first Inbox captures raw notes from the Inbox surface, the sidebar quick-capture button, and the Ctrl+Shift+K shortcut. Chat and voice can save captures through the shared assistant runtime when a live hosted or Ollama planner is available; without a live planner, Lina keeps the existing no-guess degraded behavior. Captures can be manually classified as task, project note, calendar idea, trip item, health log, or knowledge entry for later triage. |
| Chat assistant without a live AI provider | `local-only/degraded` | Lina now refuses to guess or execute assistant actions from chat unless a live hosted or Ollama planner is available. Users can still use the app surfaces directly. |
| AI diagnostics in Debug tab | `real` | The Debug surface includes runtime status, Supabase session details, hosted health and smoke tests, Ollama checks, circuit-breaker reset controls, the latest planning bundle, raw planner response, model turn, validator verdict, pending confirmation state, execution payloads, raw narration response, final assistant message, latest-turn OpenAI usage estimates, factual last-7-day OpenAI project billing and usage buckets when the separate admin-backed billing function is configured, and the latest dashboard-focus trace so task recommendations can be debugged when GPT picks or falls back. If admin billing access is missing, the panel shows a truthful unavailable state instead of simulated billing data. |
| User-facing Sync / AI Health Center | `real` | Dashboard System status summarizes local save, Supabase database state, Google Calendar, hosted OpenAI, Ollama, and Voice readiness with gentle repair actions. Settings includes the Data Sync review modal only for meaningful database/device user-data drift, defaulting to Supabase while allowing an explicit device commit. System metadata and external calendar cache drift are cleaned up automatically, and diagnostics avoid exposing raw tokens or presenting local or synced settings values as secure secret storage. |
| Dashboard task snapshot and smart Up Next | `real` | The Dashboard now surfaces a compact task queue with urgent counts plus a GPT-first `Up Next` recommendation. HELM builds grounded local candidates from tasks, habits, prayer tasks, calendar pressure, streak state, and recent feedback, lets hosted GPT review that candidate pool once per local day, and relies on the local ranker for live reshuffling the rest of the day. Prayer tasks are first-class and only enter `Up Next` during the active prayer window, in order, instead of being treated like timeless daily habits; when the Dhuhr or Maghrib window is active and the paired prayer is still upcoming, the recommendation copy now treats Dhuhr/Asr and Maghrib/Isha as paired suggestions instead of phrasing them as isolated prayers. If hosted AI is unavailable, invalid, or the user is in Ollama mode, the dashboard now says so explicitly instead of implying GPT reviewed the list, and duration chips only appear when the time comes from grounded task or calendar data instead of heuristics. |
| Voice assistant | `local-only/degraded` | Shares the same GPT-led assistant runtime as chat, including model-first intent recognition, confirmation handling, grounded ID validation, narrated final replies, and transcript correction memory for phrases the user fixes with "No, I said ...". With wake word plus STT/TTS available, Lina runs a hands-free turn-based voice session with spoken acknowledgement, a mic-ready tone after the microphone is truly live, live transcript preview, more patient 2.5-3.0 second pause handling before ending a spoken turn, automatic follow-up listening, and wake-word sessions recorded into Chat history as separate conversation threads. Settings can turn Lina off completely without removing Chat. If no live planner is available, voice refuses to guess instead of falling back to local parser commands. |
| Wake word | `real` | OpenWakeWord runs locally in-browser via WASM. |
| Deepgram speech-to-text | `real` | Requires a configured API key. |
| Browser speech fallback | `local-only/degraded` | Usable where supported, less reliable than Deepgram. |
| ElevenLabs speech output | `real` | Requires env configuration. |
| Browser speech output | `local-only/degraded` | Used when ElevenLabs is unavailable. |
| Prayer times, outcomes, deadlines, and reminders | `real` | One shell-level provider owns the validated AlAdhan Jafari timetable and canonical local-first prayer history. Every completion route asks On time or Late; explicit historical correction supports Missed without duplicate XP, while legacy checked entries remain separately labelled `unclassified`. Dashboard and Profile show accessible On-time/Late/Missed percentage segments whose denominator excludes pending opportunities and whose rounding totals 100%. Rows show final deadlines (Fajr to Sunrise, Dhuhr/Asr to Sunset, Maghrib/Isha to Jafari Midnight). Global configurable warnings, five-minute snooze, notification dedupe, timezone mismatch pauses, and Prayer Debug diagnostics are real. Native Tauri timers and Windows notifications continue while the HELM window is minimized but stop when the app process is fully exited; browser fallback requires the page to remain open. |
| Clock surface (multi-timer and stopwatch workspace) | `real` | Local-first timers and stopwatches persist through the shared store so in-progress sessions survive navigation and reloads. The Clock surface supports multiple on-demand timer and stopwatch cards, custom per-card names, stopwatch lap totals plus per-lap split times, selectable built-in alarm sounds, and completion alerts that keep pulsing until acknowledged. |
| Finance accounts, budgets, and savings goals | `real` | Local-first app data is implemented. |
| Health fast food log | `real` | Local-first fast-food tracking is implemented through the Health surface, with a quick-entry journal for venue, date, symptoms, and an overall experience rating plus a recent-history reminder view. |
| Monzo import | `real` | Live API path exists when configured. |
| Knowledge base and lifestyle tracker | `real` | CRUD is implemented. Signed-out data is local-first; signed-in data is Supabase-backed and should appear consistently across devices using the same HELM account. Knowledge entries can be moved between topics from the entry card so the topic taxonomy can evolve without recreating notes. |
| Projects hub | `real` | Local-first project management is implemented. The Projects surface includes a portfolio rail, project overview, kanban board, milestone tracking via project-linked goals, lightweight wiki pages, and local project path references. Desktop builds can browse/open local paths directly; web builds fall back truthfully to manual path entry and copy-only behavior. |
| Trips planner | `real` | Local-first multi-country trip planning is implemented with guided trip creation, ordered destination legs, per-day itinerary items, a linked booking model where transport and stay bookings automatically feed the trip budget ledger, essential-first booking editors with sensible defaults plus inline feedback for contradictory times or dates, a unified budget tab for booking-backed and manual costs across transport, food, events, rent or stay, shopping, fees, and extras, and explicit one-off calendar import when calendar sources are available. |
| GitHub integration | `placeholder/simulated` | Simulated connection flow only. |
| Slack integration | `placeholder/simulated` | Simulated connection flow only. |
| Linear integration | `placeholder/simulated` | Simulated connection flow only. |

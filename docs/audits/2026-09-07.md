# Sabah One audit and repair decisions

Audit: 7 September 2026. Final source checkpoint: KAN-311, candidate 0.2.148.
Epic: [KAN-299](https://alisablondon.atlassian.net/browse/KAN-299).
This document records source decisions and measured fixture results; the ticket's
protected release receipt establishes deployment and live acceptance.

## Decision

Keep the modular React application, domain providers, database authority,
account boundaries, and one assistant mutation executor. Remove proved unused
machinery instead of introducing a state framework or generic service layer.
Clock and Prayer retain their background behavior and provider order.

Night Compass does not consume the old recommendation state. Its globally
mounted Dashboard Focus provider nevertheless scheduled minute/expiry work,
read and wrote feedback, called hosted AI, and stored unscoped recommendations.
The synthetic enabled-AI regression reproduced those calls before removal;
the temporary hosted pause alone would conceal the problem.

KAN-308 removes that provider and Shell readiness dependency, the ranker and
Debug trace, orphan AgendaList/FocusSnapshot/PrayerTimesCard/SystemStatusPanel
and systemHealth code, taskRequestParser, authStateReload, three unused source
assets, and redundant `@types/uuid`. Runtime `uuid` retains its own declarations.
Only exclusive retired CSS selectors are removed; shared prayer outcome badges
and current dashboard styling remain.

Browser startup removes exactly `helm:dashboardFocusCache:v1` and
`helm:dashboardFocusHostedReview:v1`, including before authentication. It never
reads, copies, or migrates their contents. Storage denial produces a content-free
warning and cannot block startup. Historical `dashboardFocusFeedback` types,
collection allowlists, records, and migrations remain compatible. No SQL or
shared-record cleanup is part of this change; normal scoped revert is rollback.

## Public asset contract

The supported runtime is the browser website. Its only wake-word constructors,
`useWakeWord` and `WakeWordDebug`, explicitly map `hey_lina` to `hey_lina.onnx`.
The installed `openwakeword-wasm-browser` 0.1.1 loader follows configured keywords
and modelFiles; its default Jarvis mapping is not consulted. The contract test
exercises that loader with intercepted inference-session creation and verifies
the four retained files: Lina, melspectrogram, embedding, and Silero VAD.

The unused `hey_jarvis_v0.1.onnx` is therefore retired from the supported app
contract. No external model-serving API is declared. This does not establish
arbitrary third-party direct-link usage. The uncertain `icons.svg` URL and all
approved Life Hero assets are retained; retained static public files were
compared byte-for-byte. Generated concept HTML changes only its build links.

## Core interaction recovery (KAN-310)

The remaining failure paths were reproduced against accepted 0.2.146:
quick-prompt actions could submit twice before React rendered busy state, the
More sheet did not take focus, dirty editor dismissal lost drafts, and card
actions/Health removal lacked the required keyboard/confirmation boundary.
KAN-303's existing hosted-pause guards remain intact.

One guarded Chat helper handles typed and both quick-prompt paths with
`try/catch/finally`, retained draft/error and explicit retry into the original
conversation. Rejected optimistic messages are removed before retry so the
transcript contains one completed turn. The message asks users to check any
requested domain changes before retrying; no automatic replay is introduced.

The small `useDialog` hook serves only More and the Secret, Trip wizard and Task
editors. It provides initial focus, containment, Escape and return focus, dirty
discard confirmation and a pending-save guard where the owner exposes pending
state. Successful saves close directly. Secret comparison state follows the
existing sensitive-value clearing boundary. Calendar date selection keeps the
whole cell as its pointer target, with event buttons above it; Knowledge open
and edit actions remain separate. Health removal occurs only after confirmation.

Focused component checks cover the rejection/retry and draft/save boundaries.
Synthetic browser scenarios exercise native keyboard actions and all three
editor dismissals, including preservation of a synthetic password field, at
390 and 1440 pixels. Wheel, PageDown and focus reveal are measured for the short
mobile dialogs; More also proves reverse/forward focus wrapping and return after
Escape, close and navigation. PNGs are inspected at the actual numeric widths.
These are local UI fixtures, not funded inference or authenticated user-data
acceptance. Existing domain APIs, database schemas and navigation stay intact.

## Supported integration setup (KAN-311)

Empty authoritative integration collections decode as `[]`, which bypassed the
null-only defaults in both Settings hydration paths. Focused regressions reproduced
missing Google/GitHub setup for empty, partial and remote collections at accepted
0.2.147 (`af98ec82e0c947d8a2d6a1c7d03c9b5cd455a022`).

Initial and remote hydration now append missing supported providers by provider
identity. Every stored row, ID, status, configuration timestamp and choice remains
available to the existing autosave. A separate display projection renders one
Google/GitHub card with current support copy; it never replaces account data.
Google connection actions use the stored provider ID. Calendar's intentional
account -> source -> event hierarchy remains unchanged.

Slack/Linear simulation handlers, fake status transitions, setup scaffolding and
disconnect controls are removed. A short unavailable notice replaces them;
historical records are retained harmlessly. GitHub copy describes its actual
read-only App/evidence route. Google missing-client copy directs users to the site
operator rather than a removed Settings field or localhost deployment recipe.
Account actions wrap below details on narrow screens.

Provider-mocked browser scenarios at asserted 390/1440 widths cover empty setup,
missing Google configuration, GitHub failure/retry, duplicate and historical rows,
and explicit reconnect for two Google accounts plus revoked GitHub access.
Unit coverage checks preserved IDs/status/timestamps/choices, autosave, initial and
remote hydration. No new API, provider scope, schema or live private-account access
is introduced. Paid acceptance remains deferred under the existing amendment.
